# Architecture Decision Records

This directory holds the recorded architecture decisions for `libqr`. `AGENTS.md` states the rules; these records state **why** each rule exists and what was rejected to arrive at it.

That distinction matters in a repo built largely by agents. A rule with no recorded rationale gets reversed in good faith — a dependency added to save forty lines, DOM code moved into `core/` because it was convenient at the time. An ADR makes the constraint defensible, and makes reversing it a deliberate act with a paper trail.

## Numbering

Zero-padded four digits, monotonically increasing. Numbers are **never reused and never renumbered**, including when an ADR is superseded — links and commit messages point at numbers, and renumbering silently breaks them.

Filename: `NNNN-kebab-case-title.md`.

## Lifecycle

```
proposed  →  accepted  →  superseded
```

- **proposed** — written, not yet agreed. Fine to commit in this state; it makes the open question visible.
- **accepted** — in force. Code is expected to comply.
- **superseded** — replaced. Set `superseded-by: [NNNN]`, add a one-line note directly under the title pointing forward, and **change nothing else**.

A superseded ADR is never deleted and never edited in place. The record of what was tried and rejected is the most valuable thing in this directory — it is what stops the same idea being re-litigated every six months.

## When an ADR is required

Write one when **a future contributor could reasonably reverse the decision without realising it was a decision.**

That is the whole test. Applied:

| Situation | Where it goes |
| --- | --- |
| Choosing a layering scheme, a default renderer, a testing gate | ADR |
| Rejecting a dependency, a build step, an API shape | ADR |
| Changing a default option value or the public surface | ADR |
| "The EC level bits are not in level order" | `.memory/gotchas/` |
| "I checked whether X caused the failure; it did not" | `.memory/investigations/` |
| "Half-finished, two vectors failing, next step is Y" | `.memory/handoff/` |

Architecture decisions live here, in `docs/adr/`, and nowhere else. `.memory/` holds the ephemeral and diagnostic material — see [ADR-0010](0010-repo-committed-agent-memory.md).

## Recording obligation

**Every build decision gets recorded here, at the time it is taken — not retroactively.**

"Build decision" means anything that shapes how the library is constructed or shipped: a dependency taken or refused, a build or tooling choice, a layering or module-boundary change, an API shape, a default value, a testing gate, an entry point, a release policy. If you had to weigh options, it is a build decision.

The obligation is a **dual write**:

1. **`docs/adr/`** — the ADR itself. Full context, decision, consequences, alternatives, enforcement. This is the durable record, in the repo, readable by anyone who clones it.
2. **Agent memory** — a short pointer entry in the working agent's own memory store, of the form "decision X is recorded in `docs/adr/NNNN-slug.md`". Pointer only: never a copy of the ADR body, which would immediately drift from the file it duplicates.

Both, every time. The ADR is the record; the memory pointer is what makes a future cold-start session go and read it instead of re-deciding from scratch.

Recording happens **in the same change as the decision takes effect**, so the code and its rationale land together and neither can be reconstructed later from the other's absence.

If the work is exploratory and the decision is not yet settled, write the ADR with `status: proposed` rather than deferring it. A visible open question is useful; an unrecorded settled decision is not.

## Template

```markdown
---
status: proposed
date: YYYY-MM-DD
deciders: [Name]
supersedes: []
superseded-by: []
agents-md: []
---

# ADR-NNNN: Title

## Context and Problem Statement

## Decision

## Consequences

### Good

### Bad / costs

## Alternatives Considered

## Enforcement
```

Two additions to stock MADR:

- **`agents-md`** — which `AGENTS.md` sections this decision backs, so a rule can be traced to its rationale and vice versa.
- **`## Enforcement`** — the test, lint rule, or CI gate that makes the decision real. An unenforced decision in an agent-built repo decays within a handful of sessions. If nothing mechanical can enforce it, write "review only" and say so plainly; that is useful information, not an admission of failure.
